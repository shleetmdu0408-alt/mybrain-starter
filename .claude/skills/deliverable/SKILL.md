# deliverable — 最終成果物の作成ルール

> **このスキルが成果物ルールの正本**（保存先・命名・形式の判断・手順）。指摘の記録は `rules/corrections/deliverable.md`。

## 最初にやること：形式別デザインルールを1つだけ読む

作る形式が決まったら、**下表の該当する1ファイルだけ** `Read` する。**複数読まない**（トークンの無駄）。

| 作る形式 | 着手前に読むファイル |
|---|---|
| `.pdf` | `rules/design/pdf.md` |
| `.xlsx` | `rules/design/xlsx.md` |
| `.pptx` | `rules/design/pptx.md` |
| `.docx` | `rules/design/docx.md` |

**デザインについて新しい指摘を受けたら、その場で該当ファイルに追記する**（形式ごとに分ける）。
形式に依存しない指摘（保存先・命名・確認の取り方）だけ `rules/corrections/deliverable.md` に書く。

## 保存先と命名（例外なし）

```
outputs/deliverables/YYYY-MM-DD_主題.拡張子
```

- 日付は**作成日**（`date +%Y-%m-%d` で取る）。先頭に必ず付ける（時系列で並ぶように）
- デスクトップや `/tmp` に最終成果物を置かない
- 🔧 Vault の外（例：`../共有資料/`）に出したい場合は、このパスを書き換え、`.claude/settings.json` の
  `permissions.additionalDirectories` にそのフォルダを追加する

## 形式

**`.md` で保存しない。** 必ずドキュメント形式にする。

| 用途 | 形式 | 使うスキル |
|---|---|---|
| 読み物・レポート・配布資料 | `.pdf` | `anthropic-skills:pdf` |
| 文書・原稿・レター | `.docx` | `anthropic-skills:docx` |
| 比較表・計算・データ | `.xlsx` | `anthropic-skills:xlsx` |
| 発表・説明資料 | `.pptx` | `anthropic-skills:pptx` |

形式が明示されていなければ、内容から上表で判断し、**作る前に一言で確認**する。

## 手順

0. **形式に対応する `rules/design/*.md` を1つだけ読む**（上表）
1. 中身の根拠を Vault から集める（`wiki/`, `reports/`, `Memory.md`）
2. 事実確認 — 制度・価格・ガイドラインは **WebSearch で最新情報を確認**してから書く。
   医学的な主張は **`/paper` で一次文献に当たり、PMID / DOI を載せる**
3. 形式に対応する上記スキルを呼んでファイルを生成
4. 上記の保存先・命名規則で保存（**既存の成果物を直す場合は下の節を先に読む**）
5. **読んだデザインルールの「完了前チェックリスト」を実際に実行する**（PDF なら全ページ画像化して目視、Excel なら全シート照合）
6. 生成後に `ls -la outputs/deliverables/` で**実在を確認**してから完了報告する（推測で「作成しました」と言わない）
7. 元になった調査内容が再利用価値を持つなら、`reports/` に .md でも残し `wiki/` へリンクする

## 既存の成果物を直すとき

まず**どちらのケースか**を判断する。ここを間違えると履歴が消える。

| ケース | やること |
|---|---|
| **同じ流れの中で何度も直す**（作った直後、その場で「ここ直して」が続く） | **そのまま上書き編集**。ファイルを増やさない |
| **時間が経ってから中身をいじる**（数日〜数週間後に事実が変わった・誤りが見つかった） | **旧ファイルを `outputs/deliverables/archive/` へ移し、新しい日付で作り直す** |

### 時間が経ってからの修正の手順

1. **旧ファイルを `archive/` へ `mv`**（フォルダが無ければ作る。**中身は変えずにファイル名のまま移す**）
2. **新しい日付**で作り直す。主題は変えない
3. 旧ファイルの**全要素（シート・ページ・節）を先に列挙**し、新ファイルに揃っているか名前ベースで照合する
4. **Vault 側のリンクを新ファイル名に張り替える**（`grep -rn "旧ファイル名"` で全部拾う）
5. 新ファイルの中に**何をいつ直したか**を1行残す（Excel なら見出し直下、PDF なら奥付）

> [!warning] 判断に迷ったら「新しく作る」側に倒す
> 上書きは履歴が消えて取り返せない。ファイルが1つ増えるコストの方がずっと軽い。
> **`archive/` に入れたものは消さない。** 「いつ何がどう変わったか」を後から追えることが目的。

## どちらの場合も守ること

- **既存ファイルを先に読み、含まれていた要素を落とさない**（再生成でシートを1枚消す事故が起きやすい）
- **患者情報・個人情報を成果物に入れない。** 症例を扱う資料でも、氏名・ID・生年月日・施設名は書かない
- **制作の経緯を配布物に書かない**（`NEW` バッジ、「〇〇から変更しました」等）。変更履歴は `reports/` 側に書く

## 文体・見せ方

- 結論・要旨を先頭に、詳細は後
- 表・図解を積極的に使う（文章で並べない）
- 選択肢を出すときは推奨案を示しつつ、デメリットも明記する
