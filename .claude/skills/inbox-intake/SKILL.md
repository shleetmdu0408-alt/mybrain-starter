# inbox-intake — スマホからのメモを処理するスキル

> スマホでは Claude Code を使えない。思いついたことは Obsidian で `inbox/` に書き、
> **次にパソコンを開いたときにここで処理する**。原則：**1件ずつ、必ず行き先を決めてから移す**。

## Step 0: 未処理を洗い出す

```bash
ls -1 inbox/*.md 2>/dev/null | grep -v '/index.md$'
ls -1 inbox/ | grep -v '\.md$' | grep -v '^done$'   # md 以外の持ち込み（画像・PDF等）
```

- 0件なら「未処理なし」と伝えて終了する
- 各ファイルを Read する。**frontmatter が無くても・書式が崩れていても受け入れる**（スマホで書いたものなので雑なのが前提）

## Step 1: 1件ずつ「何をしてほしいメモか」を判定する

| 判定 | 行き先 | 動き |
|---|---|---|
| **やること・締切** | `daily/YYYY-MM-DD.md` の「今日やること」 | 追記。締切があれば太字で日付を書く |
| **知識・変動する情報**（金額・日程・進捗） | `wiki/` の正本ページ | `vault-sync` スキルの Step 2〜5 に従う |
| **調べてほしいこと** | `reports/YYYY-MM-DD-調査-主題.md` | 調べてレポートを書き、根拠の wiki へリンク |
| **論文・臨床の疑問** | `reports/` | **`paper-search`（`/paper`）で一次文献から**。記憶で答えない |
| **「こう直して」という指示** | `rules/corrections/<カテゴリ>.md` | `/correct` の書式（日付／指摘／今後どう動くか）で追記 |
| **1年で変わらない事実** | `Memory.md` | めったに無い。該当時のみ |
| **素材（PDF・画像・スライド）** | `raw/` | **Claude は `raw/` に書けない**。置き場所を提案し、移動はオーナーに依頼する |
| **判断がつかない** | — | 勝手に決めず、そのメモだけ残してオーナーに聞く |

判定に迷ったら**推測で振り分けない**。原文を引用して「これはどちらですか」と聞く。

## Step 2: 実際に処理する

- **その場でやり切れるもの（調べもの・整理・追記）は、この場でやる。** 「あとでやります」と言って残さない
- ただし**外向きの行動**（メール送信・投稿・購入）、**大きな書き換え**（3ページ以上）は**着手前に確認を取る**
- 時事性のあること（制度・価格・ガイドライン・論文動向）は記憶で答えず `WebSearch` か `/paper` で確認する

## Step 3: 原文をアーカイブする

処理が済んだファイルだけを移す。**未処理のまま移さない。**

```bash
mkdir -p "inbox/done/$(date +%Y-%m)"
mv "inbox/<ファイル名>" "inbox/done/$(date +%Y-%m)/"
```

- `inbox/index.md` は**絶対に移動・削除しない**（使い方の説明ページ）
- 削除はしない。原文は証拠として残す

## Step 4: 報告

1. **処理した件数と、1件ごとの「メモの要旨 → 何をしたか → どこに書いたか」**（1行ずつ）
2. **確認待ちで inbox に残したもの**と、その理由
3. `Home.md` の「進行中」や `Memory.md` の前提が変わるなら、その旨を指摘する（勝手に更新せず、同期するか聞く）

## やらないこと

- `inbox/index.md` を消す・書き換える
- 未処理のまま `done/` へ移す／原文を消す
- スマホ側で編集されうるファイルを Claude 側で書き換える（クラウド同期が競合コピーを作る）。inbox のファイルは**読むだけ・最後に移すだけ**
