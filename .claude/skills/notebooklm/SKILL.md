# notebooklm — 重い読み込みの外注

> NotebookLM は Google が提供する「入れた資料の中だけを読んで答えるノート」。
> **Claude が司令塔、NotebookLM が読む係。** 大量の資料を Claude が全文読むとコンテキストが尽きるので、
> 読み込みだけを外に出し、答えだけを受け取って Vault に残す。

## Step 0: 投げてよい素材かを確認する（省略禁止）

**ソースにしたものは Google に送られる。** 次のものは**絶対にソース化しない**。

- **患者に関する情報**（匿名化済みでも出さない）
- **未発表の研究データ**（投稿前の原稿・生データ）
- `Memory.md` / `daily/` / `inbox/`、`wiki/` の個人・金銭・キャリア・健康のページ
- 勤務先の内部資料、共同研究の秘密保持がかかった資料

投げてよいのは、**公開されている論文・ガイドライン・記事 URL・動画・自分で買った書籍**。
**判断に迷ったら投げず、オーナーに聞く。**

## Step 1: 外注すべきかを判断する

| 条件 | 判断 |
|---|---|
| 資料3件以上、または合計1万字超 | 外注する |
| 資料を横断した比較・音声要約が欲しい | 外注する |
| 手元のファイル1〜2個を読むだけ | 外注しない（直接読む） |
| 事実確認1個・ニュース1件 | 外注しない（`WebSearch`） |
| 論文を「**探す**」段階 | 外注しない（`paper-search` = `/paper`）|

外注しないと判断したら、その旨を1行伝えてそのまま直接処理する。
**NotebookLM は「入れた資料の中」しか答えない。** 探索は必ず PubMed 側でやる。

## Step 2: オーナーに渡す手順を出す（Claude は NotebookLM を直接操作しない）

Claude 側でやること：**投入する資料のリストと、そのまま貼れる質問文**を作る。

```
1. https://notebooklm.google.com を開き、新しいノートを作る（名前：YYYY-MM-DD_テーマ）
2. 下の資料を「ソースを追加」から入れる
   - <URL / PDF のファイル名> …
3. 読み込みが終わってから、下の質問をそのまま貼る
   ---
   <Claude が用意した質問文>
   ---
4. 返ってきた答えを、出典表示ごとこのチャットに貼り戻してください
```

質問文の作り方：

- **「要約して」と書かない。** 何を知りたいかを具体的に書く（例：「各研究の対象者数・介入期間・主要アウトカムを表にして」）
- **「資料に書かれていないことは『書かれていない』と答えて」を必ず入れる**
- 出典（どの資料のどこか）を残すよう指示する

## Step 3: 受け取った答えを検証する

- **出典が付いていない主張は採用しない。** 付いていなければ、その部分だけ原典に当たる
- **数値・PMID・年は Claude 側で確認する**（`/paper` の Step 4）。要約ツールの出す書誌情報を信用しない
- 資料に無いことが混じっていたら、その旨をオーナーに伝えて落とす

## Step 4: Vault に残す（ここを飛ばさない）

| 出たもの | 置き場所 |
|---|---|
| 調べものの答え・分析結果 | `reports/YYYY-MM-DD-調査-主題.md`（型は `rules/naming.md`） |
| 人に渡す最終成果物 | `deliverable` スキル（`/deliver`） |
| **結論そのもの** | `wiki/` の該当する正本ページへ統合 |

`reports/` に書くときは frontmatter を付け、根拠の `wiki/` ページへ `[[リンク]]` を張る。
**どの資料を NotebookLM に入れたかも記録する**（後で再現できるように）。

## やってはいけないこと

- Step 0 を飛ばして Vault のファイルや患者情報をソースにする
- 出典の無い情報を断定して `wiki/` に書く
- オーナーの Google アカウントのパスワードを聞く／代わりにログインを試みる
