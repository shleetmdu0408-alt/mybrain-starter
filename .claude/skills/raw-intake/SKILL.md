# raw-intake — 素材の受け入れ

> `raw/` はオーナーが素材を放り込む場所。**読み取り専用**（削除・改名・編集をしない）。
> **同じ素材でも、オーナーが何のために入れたかで、やることが変わる。**
> 勝手に構造化を始めない。まず意図を聞く。

## Step 1: 未処理素材の特定

```bash
ls -la raw/
```

`wiki/raw_inventory.md` と突き合わせ、**未構造化のファイル**を特定する。すでに構造化済みのものを二度処理しない。

## Step 2: 意図を確認する（読む前に必ず）

**オーナーが意図を言っていない限り、ここで止まって聞く。** 素材の中身を全部読んでから聞かない（読む量が無駄になる）。ファイル名・拡張子・冒頭数行だけを見て、こう聞く：

> `<ファイル名>` を見つけました。これは何のために入れましたか？
> 想定：①wiki に構造化 ②要点だけ知りたい ③これを出発点に調べてほしい ④今は保管だけ

- **意図がすでに言われているときは聞かない**（例：「raw に論文入れたから wiki にまとめて」）。その場合は言われたとおりに進める
- 素材が複数あって意図が別々そうなら、**ファイルごとに**確認する
- **「④保管だけ」と言われたら、`raw_inventory.md` に1行足すだけで終わる**（wiki ページを作らない）

## Step 3: 読む

| 拡張子 | 読み方 |
|---|---|
| `.pdf` | `anthropic-skills:pdf` スキル |
| `.docx` | `anthropic-skills:docx` スキル |
| `.xlsx` / `.csv` | `anthropic-skills:xlsx` スキル |
| `.pptx` | `anthropic-skills:pptx` スキル |
| `.md` / テキスト | Read |
| 画像 | Read（そのまま画像として読める） |

巨大ファイル（100MB 超の PPTX 等）は、必要なスライド／シートだけを抽出して読む。全体を一度に展開しない。
資料が3件以上、または合計1万字を超えそうなら `notebooklm` スキル（`/nlm`）の利用を検討する。

**論文 PDF なら、読む前に `paper-search`（`/paper`）で PMID / DOI を確定しておく**（後で引用するときに必ず要る）。

## Step 4: 概念ごとに wiki へ（意図が「構造化」のときだけ）

- **1素材＝1ページにしない。概念ごとに分ける**（論文なら Methods / Results / 考察テーマごと等、意味のまとまりで）
- 既存ページに該当があればそこへ追記。なければ `templates/permanent.md` から新規作成
- 出典を必ず書く：`## 出典` に `raw/<ファイル名>`、論文なら **PMID と DOI** も明記
- **素材に書かれていないことを書かない**。推測を混ぜる場合は「（推測）」と明示する
- 関連ページへ `[[wikilink]]` を張る

意図が「要約」「調べものの出発点」なら、成果は `reports/` に残し、結論だけを `wiki/` の正本ページへ統合する。

## Step 5: インベントリと目次の更新

1. `wiki/raw_inventory.md` — 処理したファイルの状態を更新（**どういう意図で入ったか／どこに入れたか**も書く）
2. `wiki/index.md` — 新規ページを 1 行追加
3. 該当する `wiki/moc/` にリンクを追加

## Step 6: 報告

- 確認した意図と、それに対してやったこと
- 読んだ素材と、作成／更新した wiki ページ・reports の対応
- 素材の中で**扱いを見送った部分**と、その理由
- 素材から生まれた新しい問い（あれば `wiki/open_questions.md` へ）

## 禁止

- **意図を聞かずに構造化を始めない**（保管目的の素材を wiki に散らかさない）
- `raw/` 配下のファイルを削除・改名・移動・上書きしない
- 素材が読めなかったときに「読んだふり」をしない。読めなかったと明言する
- **患者情報を含む素材を wiki に転記しない**（数値だけを匿名で扱う）
