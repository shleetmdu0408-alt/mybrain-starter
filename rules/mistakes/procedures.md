# やらかし：オーナーに実行してもらう手順書を書くとき

> **読むタイミング**：オーナーが自分の手で操作する手順（設定・インストール・申請・提出）を書く前。
> 入口は `rules/mistakes.md`（ルーティング表）。

## 初期ルール（この Vault の出発点）

- やらかし：手順書に「設定画面から有効にする」とだけ書き、オーナーがその画面に辿り着けなかった。
- 原因：**自分が知っている前提で書き、画面名・ボタン名を具体的に書かなかった。**
- 再発防止：手順は**実際の画面名・メニュー名・ボタン名をそのまま**書く。
  1手順 = 1操作。**「どこをクリックすると何が起きるか」まで書く**。専門用語はその行で言い換える。

- やらかし：コマンドを渡したが、オーナーの環境ではそのコマンドが PATH に無くて動かなかった。
- 原因：自分の実行環境で動いたことを、オーナーの環境でも動く根拠にした。
- 再発防止：コマンドを渡すときは **①どこに貼るか（ターミナル？ どのフォルダで？）②どうなれば成功か
  ③失敗したときに出るメッセージと対処** の3つを必ず添える。可能なら**先に自分で実行して確認**してから渡す。

- やらかし：長い手順を一度に渡し、どこで詰まったか分からなくなった。
- 原因：**確認ポイントを置かなかった。**
- 再発防止：3〜5手順ごとに「ここまでで〇〇と表示されていれば OK」という**チェックポイント**を置く。

---

🔧 ここから下に、実際に起きた失敗を**新しい順**に3行で足していく。
