# corrections — 修正指示の入口（ルーティング表）

> オーナーから受けた「こう直して」を**恒久ルール**として蓄積する場所。同じことを二度言わせないため。
> **このファイル自体にルールを書かない。** 中身は `rules/corrections/` にカテゴリ別で置き、ここは**どれを読むかを決めるだけ**（1ファイルにすると Read で全部載るため）。
> 失敗の記録は `rules/mistakes.md`（**同じ件を両方に書かない**。事件の詳細は mistakes、今後の行動指針は corrections）。

## これから何をするか → 読むファイル（1つだけ）

| これから何をするか | 読むファイル |
|---|---|
| 医学・臨床・研究の質問に答える／論文を探す | `rules/corrections/medical.md` |
| 成果物（PDF/Word/Excel/PPT）を作る／長文を書く | `rules/corrections/deliverable.md` ＋ **`rules/design/<形式>.md` を1つだけ** |
| 一次資料（メール・請求書・公的書類）を受け取った／事実を記録する | `rules/corrections/facts.md` |
| CLAUDE.md・rules・スキル・フックなど Vault の仕組みを変える | `rules/corrections/vault.md` |
| ファイル名を決める／frontmatter を書く／改名する | **`rules/naming.md` が正本** |
| 「ルールを確認して」と聞かれた | `rules/corrections/` 配下すべて |

🔧 カテゴリを増やしたくなったら、ファイルを作って**この表に1行足す**。

## 書き方と運用（AI向け）

新しい指摘を受けたら、**該当カテゴリのファイルの先頭**に3行で追記する。

```
## YYYY-MM-DD
- 指摘：（何を直してほしいと言われたか）
- 今後：（次からどう動くか。具体的な「する/しない」で）
```

- 訂正・要望を言われたら**その場で**追記する。抽象語（「丁寧に」）ではなく行動で書く
- 矛盾する新しい指示が来たら、古い行に `（YYYY-MM-DD 更新）` を付けて最新を優先
- 該当カテゴリが無ければ新しいファイルを作り、**この表に1行足す**

## 卒業ルール（上から順に試す。「3ヶ月」は最後の手段）

1. **ドメイン限定なら即移設** — 特定の話題だけの指示は、その `wiki/` ページへ移す。**日数を待たない**
2. **一般化できたら昇格** — 他の作業にも効くルールになったら `CLAUDE.md` へ1行で昇格させ、ここからは消す
3. **同種をまとめる** — 同じ原因・同じ再発防止のものは1件に統合する（別々の日付で増やさない）
4. 上のどれにも当てはまらず**3ヶ月再発なし**なら `rules/archive/` へ

- **上限は件数ではなく「読む量」。1ファイル 5,000 バイト以内**（作業のたびに読むのはファイル単位なので、コストの単位もファイル単位にする）。超えたら新規追加の前に 1〜3 を実行する
  - **統合（3）は件数しか減らさない。** 別々の日付を1つの見出しにまとめても本文は残るので、**削るか移すかしないと上限は下がらない**
- **件数もバイト数もここに書かない。** `.claude/hooks/size-check.sh` が毎回測って、超過しているときだけセッション開始時に知らせる（数字を書くと必ず古くなる）
