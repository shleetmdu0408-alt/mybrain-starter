## 4. セットアップスクリプトのログとフォント

### 「★ セットアップ版」＝ **存在しない**

以下を検索して、**該当は1件も無かった**。

- リポジトリ全体（`grep -rn "セットアップ版" .`）→ 0件
- `/var/log/` 配下、`/tmp/claude-code.log` → ヒットしたのは**自分が打った検索コマンドのエコーだけ**
- `~/.claude/session-env/` → 空

そもそも**セットアップスクリプトのログ自体がこのコンテナに無い**。`.claude/settings.json` に登録されている SessionStart フックは `inbox-check.sh` と `size-check.sh` の2つで、どちらもバージョン番号を出力しない。

「★ セットアップ版」が出るはずだと考えていた根拠がどこかにあるなら、それはこの環境には反映されていない。

### `which soffice`

```
/usr/bin/soffice
```

**あるが、これだけでは PDF 化できなかった。** LibreOffice 24.2.7 のうち `libreoffice-core` と `libreoffice-common` しか入っておらず、**Impress（プレゼン）コンポーネントが未導入**。pptx を渡すと以下で落ちた：

```
Error: source file could not be loaded
```

空の .pptx でも同じエラーになったので、ファイル側ではなく**環境側の欠落**と確定。`libreoffice-impress` を追加インストールして解決した。

### `fc-match "Yu Gothic"`

```
DejaVuSans.ttf: "DejaVu Sans" "Book"
```

**日本語フォントにすら当たっていない。** さらに悪いことに、言語を指定しても中国語フォントが返る：

```
$ fc-match "Yu Gothic:lang=ja"
wqy-zenhei.ttc: "WenQuanYi Zen Hei" "Regular"

$ fc-match "sans-serif:lang=ja"
wqy-zenhei.ttc: "WenQuanYi Zen Hei" "Regular"
```

**この環境には日本語の優先設定が無く、日本語を頼むと中国語フォントが返ってくる。** これが次章の字形問題の原因。

## 5. スライドの作り直しと /BaseFont の実測

`outputs/deliverables/` の日本語スライドを、同じ build スクリプトから作り直した。

### 実測した /BaseFont（修正前）

PDF の生バイト列を `/BaseFont` で正規表現検索した結果。印象ではなくファイルから読んだ文字列：

```
/BaseFont /DAAAAA+NotoSansCJKsc-Regular
/BaseFont /BAAAAA+NotoSansCJKsc-Bold
/BaseFont /EAAAAA+DejaVuSans-Bold
/BaseFont /CAAAAA+DejaVuSans
```

**`jp` ではなく `sc` だった。** SC は Simplified Chinese（簡体字）。
つまり**日本語のスライドが、中国語の字形セットで描かれていた**。SC と JP は一部の漢字で字形が違うため、日本人が見れば違和感の出る資料になる。

`pdffonts` でも同じ：

```
BAAAAA+NotoSansCJKsc-Bold      Type 1     Builtin   yes yes yes
DAAAAA+NotoSansCJKsc-Regular   Type 1     Builtin   yes yes yes
```

> [!warning] 前回の報告は誤りだった
> 2026-09-02 の1回目の報告で「PDF は Noto Sans CJK JP で描かれている」と書いたが、**これは実測せずに書いた推測で、実際は sc だった**。フォントは必ず PDF から読み取って確認する。

### 修正

`/etc/fonts/local.conf` を作り、`lang=ja` と `Yu Gothic` に対して `Noto Sans CJK JP` を最優先にした。

```
$ fc-match "Yu Gothic"          # 修正後
NotoSansCJK-Regular.ttc: "Noto Sans CJK JP" "Regular"
```

### 実測した /BaseFont（修正後）

```
/BaseFont /CAAAAA+NotoSansCJKjp-Regular
/BaseFont /BAAAAA+NotoSansCJKjp-Bold
```

**`jp` になった。** DejaVuSans も消え、英数字も同じ CJK JP 面から描かれるようになった。

### 上書きしたファイル

| ファイル | 状態 |
|---|---|
| `outputs/deliverables/2026-09-02_日本語スライド生成テスト.pptx` | 上書き（3枚） |
| `outputs/deliverables/2026-09-02_日本語スライド生成テスト.pdf` | 上書き（3ページ・NotoSansCJKjp 埋め込み） |
| `outputs/deliverables/src/2026-09-02_日本語スライド生成テスト_build.py` | 上書き |

スライド本文にも実測値を反映した（「SC 面が選ばれていた」「/BaseFont は NotoSansCJKjp」）。
pptx と PDF の本文を1ページずつ突き合わせ、**3ページとも文字数一致・欠落文字なし**（122字 / 468字 / 388字）。

## 6. 次のセッションに引き継ぐこと

コンテナは使い捨てのため、**このセッションで直したものは何も残らない**。次に同じことをやるなら、以下を毎回やり直す必要がある。

| やること | コマンド | 理由 |
|---|---|---|
| Impress の導入 | `apt-get install -y libreoffice-impress` | 無いと pptx → PDF が `source file could not be loaded` で落ちる |
| PDF 検証ツール | `apt-get install -y poppler-utils` | `pdftotext` `pdffonts` `pdftoppm` が無い |
| 日本語フォント優先 | `/etc/fonts/local.conf` を置いて `fc-cache -f` | 無いと日本語が**中国語字形**で PDF 化される |

自動化するなら SessionStart フックに入れるのが筋。ただし `apt-get` は毎回1〜2分かかるので、セッション開始が遅くなるトレードオフがある。
